# 需求分析流程

新增用户可见功能或跨模块变更前，先完成轻量需求分析。目标是让实现有清晰边界，不在代码阶段临时扩范围。

## 适用场景

- 新增页面、API、数据表或后台任务。
- 修改模型调用、题集导入、评分逻辑或部署结构。
- 引入新的题集格式、文件存储策略或第三方模型 provider。

## 推荐步骤

1. 写清楚背景和目标。
2. 明确第一版范围和不做事项。
3. 描述关键用户流程。
4. 列出数据模型和接口草案。
5. 明确错误处理和安全约束。
6. 写出验收标准。
7. 把后续想法放到 backlog，不塞进当前实现。

## 需求文档位置

需求文档放在：

```text
docs/requirements/
```

模板：

```text
docs/requirements/templates/requirement-template.md
```

## 实施规则

- 需求文档没有明确的内容，不应直接进入大规模技术实施。
- 如果实施中发现需求假设错误，先更新需求文档，再继续改代码。
- 第一版优先可运行、可验证、可解释，不追求一次性覆盖全部 benchmark。
